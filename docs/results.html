crashproof — results

A write-ahead log whose crash-safety is proved in Lean 4, then the compiled program is crash-tested against the proved model. A learning reimplementation of FSCQ's ideas.

Theorems

Every statement holds for all executions: a crash may strike before any block operation, the drive may lose, reorder or tear any write since the last sync, and recovery may itself crash any number of times. The axiom column is #print axioms output.

theoremin plain wordsaxioms
Atomicity
Crashproof.*.atomicity
If a crash happens at any point during commit, then after recovery the logical disk equals either the state before the transaction or the state after it.propext, Classical.choice, Quot.sound standard axioms
Durability
Crashproof.*.durability
Once commit returns, the logical disk is the transaction's result, and any crash from then on recovers to exactly that result.propext, Classical.choice, Quot.sound standard axioms
Idempotent recovery
Crashproof.*.recovery_idempotent
However many times recovery itself crashes and restarts, once a recovery completes the log is idle and the logical disk is the one the first crash determined.propext, Quot.sound standard axioms
Reads in a transaction
Crashproof.*.get_correct
A read inside a transaction returns the transaction's own writes, and the committed disk for every other block; it changes nothing on disk.propext standard axioms
Writes in a transaction
Crashproof.*.put_correct
Recording a write changes exactly one block of the transaction's logical disk and keeps each block logged at most once.propext, Quot.sound standard axioms
Sequences of transactions
Crashproof.*.commitAll_spec
A crash anywhere in a run of transactions recovers to the state after some prefix of them -- never to a state with a transaction half applied.propext, Classical.choice, Quot.sound standard axioms
Crash while idle
Crashproof.*.crash_while_idle
A crash while no commit is running loses only the uncommitted, in-memory transaction.propext, Quot.sound standard axioms
Commit (Crash Hoare triple)
Crashproof.*.commit_spec
The full pre / post / crash specification of commit, in the style of Crash Hoare Logic.propext, Classical.choice, Quot.sound standard axioms
Recovery (Crash Hoare triple)
Crashproof.*.recover_spec
The full specification of recovery: it ends idle, and a crash leaves a state recovery handles identically next time.propext, Quot.sound standard axioms

Checked in CI by scripts/check-proofs.sh: no sorry, and only Lean's three standard axioms (propext, Classical.choice, Quot.sound).

Crash harness

Model-based testing of the native executable: a random workload is run and the power is cut (inject / torn / kill); the recovered image must equal the model's state after every acknowledged transaction, optionally plus the one in flight — nothing else.

Mutation checks

Each one-line protocol bug must either stop the proofs compiling or be caught by the crash harness. Proof mutants edit the real protocol in Crashproof/Log.lean; harness mutants run broken protocols from App/Buggy.lean.

What the proofs do and do not cover

The proofs are about the model in Crashproof/Disk.lean and the protocol in Crashproof/Log.lean. They do not cover the Lean compiler, the ~90 lines of C in native/dev.c, the operating system, or the drive's firmware — the trusted base. The crash harness exists precisely to test that untrusted bridge; it found no discrepancy in 2000 crashproof runs and 2000 wren-os runs.
